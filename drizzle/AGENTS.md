# Database rules (V1 migration, legacy stays master)
- V1 tables are fed one-way from legacy by SECURITY DEFINER triggers, service_role-only, no RLS policies until their RPC lot.
- vehicles: one active per driver; capacity = registered_seats − 1 from the registration card, never invented.
- driver_documents/driver_document_checks: checks append-only so AI never overwrites a human decision.
- driver_presence mirrors drivers; availability = online/offline/paused only; busy/shared computed from rides.
- Money ≠ access: revenue only from payment_transactions status=success; driver_day_passes (one per driver per Libreville day) is access only; legacy subscriptions become FREE passes, never revenue.
- client_identities: phone-keyed on the canonical +241+8-digit form produced server-side by normalize_client_phone_ga in create_ride_public_v1 (legacy rows untouched), no auth, attached on ride INSERT; restrictions only in append-only client_restrictions; ride access still needs the per-ride token.
- ride_assignments: history of drivers per ride, mirrored from rides.chauffeur_id/status (legacy master); one active per ride, none per driver (sharing), transitions guarded, never deleted, demo never mirrored so reset_demo_data stays unblocked.
- ride_events: append-only business journal; ride-state events emitted from rides, assignment events from ride_assignments (no cross-trigger dependency); only provable events, legacy canceled = legacy_canceled_unknown, no PII in payload, demo never journaled; sort by occurred_at, id.
- driver_restrictions: operational state distinct from penalties; active derived from dates (no status column), lift needs author+reason, lifted rows frozen, never deleted, penalty_id must be same non-demo driver, no auto-restriction from refusals, not yet read by any RPC.
- associates/associate_share_rules: V1 dated shares [from,to) in Libreville days, no retroactive insert, started rules only closable (never extended, never in past), no per-associate overlap and global sum ≤100% enforced by trigger under a fixed advisory lock, no DELETE, not synced from associates_settings.
- audit_events/notification_outbox: V1 foundations only, service_role-only, no RLS policies, no producer and no worker; audit_events append-only (corrections = new event), outbox content immutable after insert with sent/failed/canceled terminal and no secrets or phone numbers in metadata/payload (top-level key check).
- Document AI (LOT 2C): server-only analysis per document version, one AI check per version (unique index), AI may only approve or require manual review — never reject, never override a human check; auto-approval re-verified in SQL against a service_role-only threshold.
- Operational eligibility: compute_driver_operational_eligibility is the single source of truth; the gate (assert_driver_documents_gate) only blocks ONLINE/pool/take_ride when onboarding_control is 'enforced' (one-way, superadmin, audited), never drop-off/close.
- Day ticket V1 (LOT 3A): driver_ticket_mode (FREE default/PAID) changes only via set_driver_ticket_mode (superadmin, reason, audited, trigger-guarded); FREE passes never create payment_transactions; PAID fails closed (XFIN_NOT_CONFIGURED) while xfin_integration_ready() is false — flip it only in a migration shipping a real tested integration; access validity = service_day today Libreville AND expires_at > now(), never status alone.
- Day ticket switch (LOT 3B): has_valid_driver_day_access(driver) is the single pass check used by ONLINE/pool/take_ride (never drop-off/close); activate_driver_day is a compat wrapper to activate_my_driver_day_v1 and never writes subscriptions (legacy history only, never revenue).
- xFin dormant (LOT 3C): single server client src/lib/xfin.server.ts (no network call without XFIN_APP_KEY/SECRET); webhook /api/public/xfin-webhook verifies X-XFIN-Signature HMAC on raw body before any write; resolution only via service_role apply_xfin_transaction_update (idempotent by xfinReference, SUCCESS activates the pass atomically, post-midnight confirmation flagged LATE_CONFIRMATION_RULE_PENDING without activation until the business rule is decided); split-payment and give-change unused.
- Frontend V1 switch (LOT 4B): legacy create_ride_public always raises CLIENT_APP_UPDATE_REQUIRED; no API role reads rides/ride_public_status directly — drivers use get_my_active_rides, admin uses admin_list_live_rides; legacy rides already active are only completed, never offered.
- Shared rides V1 (LOT 5): rides stay independent (no anchor/parent, anchor_ride_id unused by V1); shared_v1_rejection is the single server compatibility check (consent → ±45° direction → detour ≤ system_settings.shared_max_detour_km → seats ≤ vehicles.passenger_capacity) used by get_pool_v1 and re-run under the driver lock in reserve_ride_v1; seats = passenger_count of active v1 assignments (reserved+confirmed); no detour threshold or unknown capacity = sharing refused (fail closed), never a default value.
- Back-Office V1 (LOT 6): admin reads only via super_admin RPCs (admin_dashboard_v1, admin_list_rides_v1 without token/phone, admin_finance_v1, admin_associate_shares_v1, admin_list_audit_events_v1); revenue = finance_eligible_payments_v1 (success, non-refund, not refunded) only, subscriptions shown as "Legacy / simulation non encaissée"; associate shares use the rule valid on the payment's Libreville day; driver_restrictions now gate new rides only (access_blocked → ONLINE/pool/take, pool_blocked → pool/take, shared_blocked → additional shared ride), never drop-off/close; force offline never cancels; price_final correction only via admin_correct_price_final_v1 (session flag in rides_v1_workflow_guard, price_final_confirmed_at untouched); every admin business action writes audit_events.
- GPS/Notifications (LOT 7): driver position is current-only in driver_presence via update_driver_presence_v1 (own row, no history table); staleness reads system_settings.presence_stale_threshold_sec and stays unknown when unset (never a default); notification_outbox is fed by ride_events_to_outbox (one row per v1 event+recipient, dedupe key evt:<event_id>:<recipient>, in_app only, payload status only); no push worker; V1 auto-expiry not scheduled until a V1 threshold is validated.
- xFin Sandbox: XFIN_ENV=SANDBOX switches the single xfin.server.ts client to the sandbox URL with sbx_ keys only and polling (no webhook); payment_transactions.provider_environment is immutable and only PRODUCTION success counts as revenue; sandbox payments only for drivers enabled by superadmin in xfin_sandbox_testers (audited).
